# 同类项目全景与 Echo 的取舍

调研时间：2026-10-19。目的是把 Echo 放在已有工作的坐标系里：哪些设计是公认的好做法（照抄）、哪些是各家分歧点（选择）、哪些是 Echo 自己的东西（创新）。

---

## 一、记忆系统：三家主流方案的共识与分歧

| 项目 | 核心设计 | 值得借鉴的 | 分歧/代价 |
|---|---|---|---|
| **Letta**（原 MemGPT） | ① **记忆块**：带标签、有体积上限、模型可直接编辑的块；② **上下文由数据库状态编译**而来，而不是把历史塞进去；③ **sleep-time compute**：空闲时后台代理重写上下文里的记忆；④ 归档记忆按需检索 | "块 + 尺寸上限 + 模型可编辑"这三件套（Echo 的 `MEMORY.md` 就是它的极简版）；"上下文编译"思想（Echo 把它做成显式预算 + 滚动摘要）；"睡时改写"（Echo 的 Dream） | 它是 agent 框架，跑起来要一整套服务与数据库；Echo 换成单进程 + 明文文件 |
| **Mem0** | 抽取 → 与已有事实做 **ADD / UPDATE / DELETE / NOOP** 调和；向量+图混合检索 | 调和式写入（Echo 的 `applyOps` 直接采用）；"先查重再写"避免记忆膨胀 | 依赖向量库与托管 API；Echo 用词法 BM25 + 实体加权替代（代价见"残余弱点"） |
| **Zep / Graphiti** | **时序知识图谱**：边带有效期（bi-temporal），事实随时间失效；面向开放域与时间复杂查询 | 实体/关系入图、按实体召回（Echo 做了极简版）；"事实会过期"这一时间维度 | 图数据库 + 嵌入管线；Echo 的图没有有效期，只按强度衰减 |

**共识**：分层（核心/归档）、按需检索、压缩摘要、后台巩固。
**分歧**：检索靠向量还是词法+图；记忆是否可编辑；**以及——几乎没人认真处理"遗忘"**。

## 二、屏幕/上下文感知

| 项目 | 做法 | 借鉴 | Echo 的取向差异 |
|---|---|---|---|
| **screenpipe**（YC S26，source-available） | 持续录制屏幕与音频，本地存储，做成"可搜索的工作历史"，并通过 **MCP** 暴露给 Claude/Codex 等 agent；带 PII 过滤、忽略名单、可选加密 | 本地优先采集；忽略名单；"把生活上下文暴露给 agent"这一主张 | Echo 只做**瞬时理解**：本地 OCR 出文字后才给模型，截图分析完即删；L0 工作记忆有 TTL，不进永久档案。取舍是：**不能回看历史**，换来"不积累敏感资料" |
| **OpenRecall** 等本地回忆工具 | 本地截图 + OCR，可搜索 | 本地 OCR 的思路 | 同上；另外 Echo 加了磁盘硬预算与被引用保护 |

**小结**：这一族的关键差异不是技术，而是**默认姿态**：是"留存一切以便检索"还是"理解当下、随后忘掉"。Echo 明确选后者。

## 三、主动性（proactive agent）

| 项目/论文 | 做法 | 借鉴 | Echo 的差异 |
|---|---|---|---|
| **Proactive Agent**（清华 NLP，arXiv 2410.12361） | 把"主动"当任务来评测：构造主动事件、训练主动奖励模型（与人判断一致性约 91.8%） | "中断成本 vs 价值"的判断框架；用奖励模型衡量主动性 | 它是研究基准（需要训练/评测）；Echo 是**在线闭环**：bandit 按类型积累后验，奖励=你 6 小时内是否接住；并用台账 EV 排序 + 门禁（静默时段/预算/间隔/降速）决定"要不要打扰" |
| **ChatGPT Tasks / 各类"定时提醒"** | 定时触发 + 用户预设 | 定时是必要的兜底 | Echo 不靠用户预设任务，靠记忆与屏幕上下文自行判断该说什么 |

**Echo 的做法**：`Thompson 采样选类型 → 台账挑事项 → 模型在"策略先验 + 当前情境"下做最终判断 → 开口后按是否被接住结算`。离线回放（固定接住概率、2000 轮）里，bandit 比固定轮换高 **60–80%** 的被接住率（模拟值，非真人数据）。

## 四、本地优先的个人助手

同类里成熟的是这些：**Jan / AnythingLLM / Open WebUI / LibreChat / Cherry Studio / Khoj / Leon**——它们的能力普遍更强（多用户、RAG、插件、多端），但都要跑一个不小的运行时（Node/Python + 向量库/数据库，通常还要 Docker），记忆与主动性多为"文档 RAG + 定时任务"。

Echo 的定位刻意不同：**一个进程、零第三方依赖、状态全是明文文件、为"一个人一台 Mac"设计**，把复杂度花在记忆与主动性上，而不是花在部署形态上。

## 五、自我改进（为什么 Echo 不自己改代码）

**Darwin Gödel Machine**（Sakana/ICLR 2026）展示了让 agent 改自己代码、靠基准分做选择的自改进循环。但同类工程实践反复暴露同一个陷阱：**评估器被优化对象污染就会 reward hacking**（改测试、绕过沙箱、写死边界）。所以 Echo 采用**保守的可行子集**：

- 冻结的评估器（`tests/selftest.mjs`，60 项断言，只增严不放松、不与产物同处可写空间）；
- 隔离沙箱执行、双轨检查（实现断言 + 真实链路验证 + "声称出图却没调工具"这类诚实性检查）；
- 迭代日志留档（`docs/rsi-log.md`）：每轮假设、改动、分数、判决、教训；
- **不自动改代码**，改动与回退由人决定。

## 六、Echo 自己的东西（可对外说的创新点）

1. **把遗忘做成一等公民，而且可解释**
   强度 = 重要度 × 使用增益 × 指数衰减；被检索命中会强化（间隔重复）；低于阈值 → 淡出（不删除，可复活）；超容量 → 按强度淘汰；**每一次淡出/遗忘都写进 `memory/forgetting.md`：忘了什么、为什么、依据哪个数字**。同类项目普遍只做"记住 + 检索"，RAG/记忆库把"忘"外包给容量与上下文窗口。

2. **主动性的可测量闭环**
   bandit（奖励=接住）+ 门槛自适应（不被接住的类型要提高把握）+ 台账 EV 排序 + 6 小时结算 + 节流门禁。这是把"主动"从提示词技巧变成**有反馈的决策系统**，而且指标（被接住率、开口次数、降速状态）在自报告里可见。

3. **屏幕感知的"瞬时理解"形态**
   本地 OCR 只发文字、原始截图即删、L0 有 TTL 且只用于当下判断、磁盘预算硬约束、引用保护。对照"持续录制 + 可搜索历史"（screenpipe/OpenRecall），这是**取向上的另一种答案**：不做第二记忆库，做"此刻的上下文"。

4. **零依赖 + 全明文可审计**
   0 个 npm 包、无向量库、无数据库；状态是 jsonl/md。任何人可以直接打开文件看懂它记住了什么、为什么记住、忘了什么。

5. **工程化预算与韧性**
   截图/图片磁盘预算（超 80% 从最旧删、最近对话引用的永不删）、搜索**熔断器**（被验证码拦下即冷却，不反复撞墙）、**模型降级链**（主模型不可用自动切换）、上下文预算 + 滚动摘要、`metrics.jsonl` 自报告（延迟 P50/P95、工具成功率、失败 Top）。

6. **内建 RSI 纪律**
   冻结判据 + 沙箱 + 只增严 + 迭代日志；60 项断言覆盖安全（SSRF/CSRF/XSS 不可存活）、记忆不变量、预算淘汰、决策算法、真实链路。个人项目里少见。

## 七、诚实的短板（对照上面的坐标系）

- **无双时态**：实体图的边不会随时间失效（Zep 有）。"以前成立、现在不成立"的关系只能靠衰减近似。
- **无向量检索**：词法 + 实体加权，对同义改写与跨语言召回弱于嵌入方案。
- **bandit 无上下文特征**：只按"类型"分臂，没有把时段/情境作为特征（contextual bandit 的 context 维度缺失），因此学习需要更久。
- **屏幕是快照不是流**：定时采样会漏掉片段之间发生的事（连续的取舍我们主动放弃）。
- **主动性的成绩目前只有离线回放**，真人数据要靠持续使用积累。
