# 产品决策演变记录

按时间顺序记录**我们如何把这个产品做成现在这样**：每个阶段做了什么决定、为什么这么定、当时否掉了什么。功能清单在 README，这里只留判断与边界。

---

## 阶段 0 · 起点（2026-10-16）

**原始诉求**：本地跑一个 chat 窗口，调自己的 API；"该有的都有"；长期挂着；最好能联网搜索；简洁、轻量、优雅。

**当时的判断与取舍**

- **零第三方依赖**：那时只有一个模型调用需求，自写 SSE/tool-call 循环足够；换来"没有构建步骤、没有 node_modules、任何文件都能直接读懂"。*（后续在阶段 8 被部分修订——见下）*
- **局域网 + 口令** vs 仅本机：最初按"随时随地"选了局域网 + 口令，并默认开启。
- **选搜索引擎**：实测 DuckDuckGo 不可达、Bing 抓取会跳验证码、360/搜狗可用（0.5–2.5s）；阿里云托管搜索要 28–37s。→ 定为"抓取优先、托管兜底"。
- **模型清单**：从网关 `/models` 实测后按系列分组，只列真正可用的；视频/语音当场实测不可用（`url error`/空响应/InternalError），所以**不做假适配**，只在配置里预留。

## 阶段 1 · 记忆与遗忘（同一天）

**决定**：记忆分四层（L0 工作记忆 / L1 事实 / L2 核心 MEMORY.md / L3 归档与图谱），并把**遗忘**做成一等公民：强度 = 重要度 × 使用增益 × 时间衰减；命中强化、久用淡出、超容量按强度淘汰；每次遗忘写进 `forgetting.md` 并给出依据数字。

**为什么**：借 MemGPT/Letta 的"记忆块 + 睡时改写"、Mem0 的"抽取→调和"、Zep 的实体图，但业界普遍只做"记住 + 检索"，把"忘"外包给上下文窗口——而那恰恰是个人助手最需要判断力的地方。用户给的那句"我们不是我们记住的东西，而是我们忘记的东西"成了设计原则。

**否掉的**：向量库（当时网关无 embedding 接口，且引入依赖会打破"零依赖"）；把遗忘做成硬删除（改为可复活）。

## 阶段 2 · 主动服务（同一天）

**决定**：固定"主对话"跨模型长期连续；后台定时判断要不要开口；用 **Thompson 采样 bandit** 选开口类型（奖励 = 用户是否接住，6 小时未回应按 0 结算），门槛随表现自适应，台账用确定性 EV 排序，外加静默时段/每日预算/最小间隔/连续被忽视降速。

**为什么**：这类"主动"最常见的失败是变成骚扰。把"要不要打扰"做成**有反馈的决策系统**而不是提示词技巧，才能解释、能调、能量化。回放实验（2000 轮）比固定策略高 60–80%，并且**明确标注是模拟**。

**否掉的**：让用户预设定时任务（那是提醒工具，不是 agent）；一开始就做多臂上下文特征（样本不够，先按类型分臂）。

## 阶段 3 · 屏幕感知与隐私默认（同一天）

**决定**：菜单栏 App 采集 + **本地 OCR（Apple Vision）**；默认只把文字发模型、原始截图分析完即删、锁屏/空闲跳过、工作记忆有 TTL。**默认关闭**，只有 `deep` 记忆档才打开。

**为什么**：对照 screenpipe/OpenRecall 那条"持续录制 + 可搜索历史"的路，我们选"瞬时理解"——不做第二记忆库，也就不会积累敏感资料。

**过程中的教训**：我曾误执行 `tccutil reset ScreenCapture`，把授权清掉；后来又因为反复重编 `build/EchoBar` 导致 macOS 把每次重编当"新 App"而反复要授权。→ 见阶段 9。

## 阶段 4 · 存储预算与"全部忘掉"（同一天）

**决定**：截图 200MB/3 天、生成图 300MB/60 天，超 80% 从最旧删，**被最近对话引用的图片永不删**；界面提供"全部忘掉"（记忆或连会话），并在遗忘日志留一条可解释记录。

**为什么**：用户明确要求"不能用截图垃圾占满"。隐私也要有兜底动作，而不是只能删文件。

## 阶段 5 · RSI：冻结评估器（同一天）

**决定**：内建 `tests/selftest.mjs`——隔离沙箱（自带数据目录与配置）、断言**设计不变量**而不是实现细节、判据**只增严不放松**、迭代写进 `docs/rsi-log.md`；不自动改代码。

**为什么**：自改进领域最可靠的教训是"评估器被优化对象污染就 game over"。个人项目里少见的，是**把尺子冻结并公开**。这一步立刻抓出真缺陷（`entitiesInQuery` 未导入、`local.token` 懒创建、配置改了不生效），而不是靠"感觉没问题"。

## 阶段 6 · 打包分发（同一天）

**决定**：DMG（通用二进制 arm64+x86_64、含 `Echo.app`、双击安装器、卸载器）+ 源码包；`git archive` 只打跟踪文件；**发布件本身当被测物**——挂载 DMG → 临时 HOME 试装 → 用装出的副本跑自测 → 断言 `echo.env` 600。

**过程中的三处流程缺陷**（都是从"下载回来验证"里发现的）：源码包在提交**前**打的（版本对不上）→ 打包脚本改为**拒绝脏树**；`upstream: {}` 还原不掉桩地址（深合并不删键，只在全新克隆下暴露）→ 显式置空；缺 `package-lock.json` 的发布件装不起来 → 打包断言。

## 阶段 7 · 社区化：BYOK、可插拔、去自用痕迹（2026-10-19）

**决定**：默认不预设任何厂商端点；六步引导（端点预设 → 测试并拉取模型 → 模型 → 记忆档位 → 搜索链 → 权限）；搜索变成**提供方链**（none/scrape/gateway/tavily/brave/bocha/searxng/custom，顺序即优先级）；记忆档位（off/light/standard/deep）选档即写实具体旋钮；`config.json` 取消跟踪；密钥只进 `echo.env`（600）。

**为什么**：用户指出"自用痕迹太明显"。判断：**产品化不是加功能，而是把"我的选择"从代码里搬到配置与引导里**，并且把"不该出现的默认值"写成不变量（自测里有一条专门断言默认配置不含某家厂商）。

## 阶段 8 · 定位与门面（同一天）

**决定**：英文 hero 版式做首页（居中标题 + 引语"我们不是我们记住的东西，而是我们忘记的东西" + 克制徽章 + 横向导航），中文版 `README.zh-CN.md`；定位收敛为 **"BYOK personal agent featuring proactive agency"**；补 `docs/landscape.md`（与 Letta/Mem0/Zep/screenpipe/Proactive Agent/DGM 的对照）与诚实的短板清单。

**否掉的**：把首屏做成功能罗列。宁可先讲清"它是什么、不是什么"。

## 阶段 9 · 伴随模式与"降低打扰"（同一天）

**决定**：伴随模式默认关；打开后秒级看屏幕，但**先做变化检测**（同屏不调模型）、有每小时预算与最小间隔、连续被忽略自动冷却；气泡不抢焦点、12 秒自淡、点开进小对话窗。随后针对反馈修两处：**气泡淡出后被反复重弹**（改为 `expired` + `since` 过滤）、**授权反复要**（App 固定路径 + ad-hoc 签名，`install.sh` 检测到已装 App 就跳过重编）。

**为什么**：这是"干扰太严重"的直接教训。结论写进原则：**默认静默、opt-in、自身从不主动弹权限框**。

## 阶段 10 · 能动手：工作区执行与运行编排（2026-10-20）

**决定**：新增受控工作区执行（路径越界校验、大小上限、写入串行化、中止传播）与运行编排（`data/runs/<id>/run.json` 状态机、**单次生效的审批**、取消清场、重启不重放已完成工作）；**取消传播**贯穿搜索/网关/出图/网页抓取/文件写入，各有回归用例；承诺追踪独立成模块。

**为什么**：从"会说话"走到"能动手"是个人 agent 的必经一步，但必须带着在记忆上那套纪律——**有预算、可解释、可回滚**。审批是这层纪律的界面。

**代价（已记录）**：引入官方 `@modelcontextprotocol/sdk`，打破"零依赖"。处理方式是把成本转移到打包侧：`install.sh` 先 `npm ci` 再动服务、**DMG 内置 node_modules**（离线可装）、源码包缺锁文件就拒绝发布。

## 阶段 11 · 主动研究、关系档案、截止核对（2026-10-20）

**决定**：① 从新对话**发现事务**（显式开启、引用真实用户消息、七天待确认期、每日 20 次模型调用上限）；② 研究复用现有 harness（**只读工具白名单**，不给后台 Shell/MCP/外部写权限；准备最多 2 次/目标、24 小时 5 次）；③ 截止日期**逐项核对**（保存来源原文、只认用户确认的官方域名，日期不补造时刻/时区）；④ **克制的关系感知**（相处方式 +手动维护的人物备注，**不做情绪档案、不做情绪提醒、不从屏幕推断心理**）；⑤ PDF 解析隔离在 worker 线程（5MB / 40 页 / 15 秒上限），Node 门槛提到 22.13。

**为什么**：这些能力最容易滑向"过度推断"。所以每条都配了硬边界：发现要引用原话、研究只读且限量、日期不猜时刻、关系只用手动资料。

**首版边界（保持诚实）**：不自动接入浏览器/邮箱/日历；Mac 睡眠期间不检查；扫描版 PDF 无文字层时报不可读；研究质量与漏报率**尚未用真实使用评估**，不声称生产力增益。

## 贯穿始终的十条判断（跨阶段复用的原则）

1. **默认静默**：新能力默认关（屏幕、伴随、后台研究、通知各自独立开关）；要开由用户显式开。
2. **打扰有成本**：任何主动行为都要有预算、间隔、退避和可解释的"为什么"。
3. **遗忘是功能**，不是清理；每次遗忘都要能说出依据。
4. **能解释 > 能自动化**：先让判断可见（意图/缺口/假设/ragione），再谈自动化程度。
5. **尺子冻结**：评估器只增严、隔离沙箱、发布件当被测物；不准为了发版放松判据。
6. **密钥边界**：密钥只在 `data/echo.env`（600）与进程环境，配置里只记"读哪个变量"，永不进 git、不进日志。
7. **可回滚**：改动尽量局部可回退（快照、备份、审批、取消、expired 而非删除）。
8. **不假装**：网关没有的能力不写适配层；模拟结果标成模拟；未验证的事说未验证。
9. **成本转到工程侧**：用户不该为依赖、缓存、权限这些事付代价（DMG 内置依赖、资源版本号、固定安装路径）。
10. **发布流程本身要防呆**：脏树拒绝打包、版本单一来源、包内版本断言、锁文件断言、这份记录必须更新。

## 待决与已知缺口

- **依赖债**：现在是 2 个运行时依赖（MCP SDK、pdfjs-dist）。是否把 MCP 客户端回退为可选（动态 import + 回退实现）以恢复"零 npm 安装即可用"，尚未决定。
- **未验证**：研究质量/漏报率、伴随模式的真实接受度、bandit 的真人数据——都需要真实使用几天后回看 `./bin/echo diag`。
- **未做**：computer use（模型提议、App 执行的 GUI 层）仍在路线图；视频/语音受网关限制。
- **发布与源码**：**alpha.6 已公开发布**，包含主动研究与关系感知。此后源码中的 URL 解析与存储清理修复尚未重新打包发布；安装包内容以对应发布标签为准。
