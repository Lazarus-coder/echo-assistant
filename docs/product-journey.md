# 产品决策演变记录

按时间顺序记录**我们如何把这个产品做成现在这样**：每个阶段做了什么决定、为什么这么定、当时否掉了什么。功能清单在 README，这里只留判断与边界。

---

## 阶段 0 · 起点（2026-10-16）

**原始诉求**：本地跑一个 chat 窗口，调自己的 API；"该有的都有"；长期挂着；最好能联网搜索；简洁、轻量、优雅。

**当时的判断与取舍**

- **零第三方依赖**：那时只有一个模型调用需求，自写 SSE/tool-call 循环足够；换来"没有构建步骤、没有 node_modules、任何文件都能直接读懂"。*（后续在阶段 8 被部分修订——见下）*
- **局域网 + 口令** vs 仅本机：最初按"随时随地"选了局域网 + 口令，并默认开启。
- **选搜索引擎**：实测 DuckDuckGo 不可达、Bing 抓取会跳验证码、360/搜狗可用（0.5–2.5s）；阿里云托管搜索要 28–37s。→ 定为"抓取优先、托管兜底"。
- **模型清单**：从网关 `/models` 实测后按系列分组，只列真正可用的；视频/语音当场实测不可用（`url error`/空响应/InternalError），所以**不做假适配**，只在配置里预留。

## 阶段 1 · 记忆与遗忘（同一天）

**决定**：记忆分四层（L0 工作记忆 / L1 事实 / L2 核心 MEMORY.md / L3 归档与图谱），并把**遗忘**做成一等公民：强度 = 重要度 × 使用增益 × 时间衰减；命中强化、久用淡出、超容量按强度淘汰；每次遗忘写进 `forgetting.md` 并给出依据数字。

**为什么**：借 MemGPT/Letta 的"记忆块 + 睡时改写"、Mem0 的"抽取→调和"、Zep 的实体图，但业界普遍只做"记住 + 检索"，把"忘"外包给上下文窗口——而那恰恰是个人助手最需要判断力的地方。用户给的那句"我们不是我们记住的东西，而是我们忘记的东西"成了设计原则。

**否掉的**：向量库（当时网关无 embedding 接口，且引入依赖会打破"零依赖"）；把遗忘做成硬删除（改为可复活）。

## 阶段 2 · 主动服务（同一天）

**决定**：固定"主对话"跨模型长期连续；后台定时判断要不要开口；用 **Thompson 采样 bandit** 选开口类型（奖励 = 用户是否接住，6 小时未回应按 0 结算），门槛随表现自适应，台账用确定性 EV 排序，外加静默时段/每日预算/最小间隔/连续被忽视降速。

**为什么**：这类"主动"最常见的失败是变成骚扰。把"要不要打扰"做成**有反馈的决策系统**而不是提示词技巧，才能解释、能调、能量化。回放实验（2000 轮）比固定策略高 60–80%，并且**明确标注是模拟**。

**否掉的**：让用户预设定时任务（那是提醒工具，不是 agent）；一开始就做多臂上下文特征（样本不够，先按类型分臂）。

## 阶段 3 · 屏幕感知与隐私默认（同一天）

**决定**：菜单栏 App 采集 + **本地 OCR（Apple Vision）**；默认只把文字发模型、原始截图分析完即删、锁屏/空闲跳过、工作记忆有 TTL。**默认关闭**，只有 `deep` 记忆档才打开。

**为什么**：对照 screenpipe/OpenRecall 那条"持续录制 + 可搜索历史"的路，我们选"瞬时理解"——不做第二记忆库，也就不会积累敏感资料。

**过程中的教训**：我曾误执行 `tccutil reset ScreenCapture`，把授权清掉；后来又因为反复重编 `build/EchoBar` 导致 macOS 把每次重编当"新 App"而反复要授权。→ 见阶段 9。

## 阶段 4 · 存储预算与"全部忘掉"（同一天）

**决定**：截图 200MB/3 天、生成图 300MB/60 天，超 80% 从最旧删，**被最近对话引用的图片永不删**；界面提供"全部忘掉"（记忆或连会话），并在遗忘日志留一条可解释记录。

**为什么**：用户明确要求"不能用截图垃圾占满"。隐私也要有兜底动作，而不是只能删文件。

## 阶段 5 · RSI：冻结评估器（同一天）

**决定**：内建 `tests/selftest.mjs`——隔离沙箱（自带数据目录与配置）、断言**设计不变量**而不是实现细节、判据**只增严不放松**、迭代写进 `docs/rsi-log.md`；不自动改代码。

**为什么**：自改进领域最可靠的教训是"评估器被优化对象污染就 game over"。个人项目里少见的，是**把尺子冻结并公开**。这一步立刻抓出真缺陷（`entitiesInQuery` 未导入、`local.token` 懒创建、配置改了不生效），而不是靠"感觉没问题"。

## 阶段 6 · 打包分发（同一天）

**决定**：DMG（通用二进制 arm64+x86_64、含 `Echo.app`、双击安装器、卸载器）+ 源码包；`git archive` 只打跟踪文件；**发布件本身当被测物**——挂载 DMG → 临时 HOME 试装 → 用装出的副本跑自测 → 断言 `echo.env` 600。

**过程中的三处流程缺陷**（都是从"下载回来验证"里发现的）：源码包在提交**前**打的（版本对不上）→ 打包脚本改为**拒绝脏树**；`upstream: {}` 还原不掉桩地址（深合并不删键，只在全新克隆下暴露）→ 显式置空；缺 `package-lock.json` 的发布件装不起来 → 打包断言。

## 阶段 7 · 社区化：BYOK、可插拔、去自用痕迹（2026-10-19）

**决定**：默认不预设任何厂商端点；六步引导（端点预设 → 测试并拉取模型 → 模型 → 记忆档位 → 搜索链 → 权限）；搜索变成**提供方链**（none/scrape/gateway/tavily/brave/bocha/searxng/custom，顺序即优先级）；记忆档位（off/light/standard/deep）选档即写实具体旋钮；`config.json` 取消跟踪；密钥只进 `echo.env`（600）。

**为什么**：用户指出"自用痕迹太明显"。判断：**产品化不是加功能，而是把"我的选择"从代码里搬到配置与引导里**，并且把"不该出现的默认值"写成不变量（自测里有一条专门断言默认配置不含某家厂商）。

## 阶段 8 · 定位与门面（同一天）

**决定**：英文 hero 版式做首页（居中标题 + 引语"我们不是我们记住的东西，而是我们忘记的东西" + 克制徽章 + 横向导航），中文版 `README.zh-CN.md`；定位收敛为 **"BYOK personal agent featuring proactive agency"**；补 `docs/landscape.md`（与 Letta/Mem0/Zep/screenpipe/Proactive Agent/DGM 的对照）与诚实的短板清单。

**否掉的**：把首屏做成功能罗列。宁可先讲清"它是什么、不是什么"。

## 阶段 9 · 伴随模式与"降低打扰"（同一天）

**决定**：伴随模式默认关；打开后秒级看屏幕，但**先做变化检测**（同屏不调模型）、有每小时预算与最小间隔、连续被忽略自动冷却；气泡不抢焦点、12 秒自淡、点开进小对话窗。随后针对反馈修两处：**气泡淡出后被反复重弹**（改为 `expired` + `since` 过滤）、**授权反复要**（App 固定路径 + ad-hoc 签名，`install.sh` 检测到已装 App 就跳过重编）。

**为什么**：这是"干扰太严重"的直接教训。结论写进原则：**默认静默、opt-in、自身从不主动弹权限框**。

## 阶段 10 · 能动手：工作区执行与运行编排（2026-10-20）

**决定**：新增受控工作区执行（路径越界校验、大小上限、写入串行化、中止传播）与运行编排（`data/runs/<id>/run.json` 状态机、**单次生效的审批**、取消清场、重启不重放已完成工作）；**取消传播**贯穿搜索/网关/出图/网页抓取/文件写入，各有回归用例；承诺追踪独立成模块。

**为什么**：从"会说话"走到"能动手"是个人 agent 的必经一步，但必须带着在记忆上那套纪律——**有预算、可解释、可回滚**。审批是这层纪律的界面。

**代价（已记录）**：引入官方 `@modelcontextprotocol/sdk`，打破"零依赖"。处理方式是把成本转移到打包侧：`install.sh` 先 `npm ci` 再动服务、**DMG 内置 node_modules**（离线可装）、源码包缺锁文件就拒绝发布。

## 阶段 11 · 主动研究、关系档案、截止核对（2026-10-20）

**决定**：① 从新对话**发现事务**（显式开启、引用真实用户消息、七天待确认期、每日 20 次模型调用上限）；② 研究复用现有 harness（**只读工具白名单**，不给后台 Shell/MCP/外部写权限；准备最多 2 次/目标、24 小时 5 次）；③ 截止日期**逐项核对**（保存来源原文、只认用户确认的官方域名，日期不补造时刻/时区）；④ **克制的关系感知**（相处方式 +手动维护的人物备注，**不做情绪档案、不做情绪提醒、不从屏幕推断心理**）；⑤ PDF 解析隔离在 worker 线程（5MB / 40 页 / 15 秒上限），Node 门槛提到 22.13。

**为什么**：这些能力最容易滑向"过度推断"。所以每条都配了硬边界：发现要引用原话、研究只读且限量、日期不猜时刻、关系只用手动资料。

**首版边界（保持诚实）**：不自动接入浏览器/邮箱/日历；Mac 睡眠期间不检查；扫描版 PDF 无文字层时报不可读；研究质量与漏报率**尚未用真实使用评估**，不声称生产力增益。

## 阶段 12 · 边界失败也要如实处理（2026-10-20）

**决定**：无法解析的请求 URL 返回明确的 400 错误；存储清理只在文件确实删除后累计释放空间，删除失败的文件继续计入占用。

**为什么**：异常输入不应中断服务，清理报告也不能把“尝试过”当成“已完成”。这两处修复补上回归检查，避免成功路径掩盖边界错误。

## 阶段 13 · 从源码说明到产品入口（2026-10-20）

**决定**：重写中英文 README，新增双语产品发布页，把用途、能力边界、下载、首次设置与问题反馈串成完整路径；开发操作移入独立指南。安装说明增加“打开聊天 → 检查模型连接 → 收到回复”的成功判断，并提供状态、日志和反馈入口。

**为什么**：第一次接触产品的人需要知道能做什么、怎样开始，以及卡住后去哪里找原因。版式与文案可以更完整，但 **alpha 状态、模型数据去向、网络默认值和签名限制必须同时说清楚**；下载链接始终对应已经公开的安装包，不能把仓库新功能误写成已发布功能。

## 阶段 14 · 让任务进度和结果可核对（2026-10-20）

**决定**：对话和执行详情展示当前动作、实际步骤计数、错误原因与结果入口；完成、失败、停止、预算耗尽、连接中断分别呈现。消息保存执行终态，刷新后可以回看；打开详情时仍持续更新，并保留查看输出的焦点。

**为什么**：用户需要判断“正在做什么、做到了哪里、结果在哪里”。不能把断流当完成，也不能把停止等同于撤销。停止后保留已完成的步骤与部分回复，未执行的工具说明原因；停止请求防重复提交，失败后可以重试。

**验证边界**：上一轮相关回归 130 项通过，并完成本地模拟模型端点的浏览器验收。这验证了状态和交互路径，不代表真实模型的任务质量已经得到评估。

## 阶段 15 · 本地候选包与打包隔离（2026-10-20）

**决定**：将当前源码整理为 **0.1.0-alpha.7 本地候选版**，生成 DMG 和 ZIP；隔离试装只写临时目标目录，遵守不启动服务、不打开应用的验证选项，并清理继承的运行配置变量。自测屏蔽共享截图缓存目录的枚举，避免清理用户文件。公开发布是独立步骤，本轮不创建 GitHub Release。

**为什么**：需要验证的是“用户拿到的包能否正确安装”，同时验证过程不能读取真实配置、使用真实凭据或改动正在运行的实例。包内版本、依赖、安装结果和校验和随构建核对，具体构建结果记录在[该版本说明](release-notes-0.1.0-alpha.7.md)中。

## 阶段 16 · 让跟进从面板走进对话（2026-11-05）

**发现**：真实数据里记忆与 Dream 一直在工作（49 条事实、7 次 Dream），但跟进目标、后台准备与运行记录一直是 **0**。不是能力缺失——创建目标、后台研究、主动交付的整条链路都已实现，唯一的入口却藏在面板里；对话里没法让 Echo 把一件事"接过去"。

**决定**：给模型四个跟进工具：`follow_up_create / follow_up_list / follow_up_update / follow_up_complete`。只在用户明确说"帮我盯着 / 持续跟进 / 到点提醒 / 帮我查清楚"时创建；创建后沿用既有准备预算、后台研究权限与主动交付链路，不新增第二套调度。完成必须引用用户最近一条消息的原话，模型不能自行判断完成。顶栏显示「跟进 · N」。

**为什么**：把"持续跟进"从配置动作变成对话动作，才符合"接住思路，继续向前"的产品承诺；同时保留原有纪律——默认静默、预算、可解释、不假装。

**边界**：研究型跟进仍需用户先在设置里开启后台研究；研究关闭时工具明确拒绝并说明如何开启，不降级假装。对话里不能创建文件夹范围或文档范围的目标（这些仍只在本机面板配置）。

## 阶段 17 · 让 Dream 的线索一键变成跟进（2026-11-05）

**发现**：Dream 一直在产出待跟进线索（真实数据里 3 条），但采纳入口只存在于「主动服务」面板的完整编辑器里；主动消息本身只说不做。

**决定**：当主动消息锚定某条 Dream 线索时，消息随附一键接管提案（标题、完成标准、截止日期、线索 id），主对话直接渲染「加入跟进」按钮。用户点击后才创建目标，走与面板相同的校验、预算与准备队列；线索已过期或已在跟进中时不重复创建。提案由固定模板生成，不为此额外调用模型。

**为什么**：Echo 自己发现 → 用户一次确认 → 后台接管，是"主动服务"从提醒变成接手的最短路径；仍然坚持"用户确认之前不创建任何目标"。

**边界**：按钮只在消息锚定 Dream 线索时出现；用户不点则不产生任何状态；一键创建不附带研究范围（研究仍需在面板按目标开启）。

## 阶段 18 · 回来简报（2026-11-05）

**发现**：接力链路补齐后还差最后一环——用户回来时看不到"我不在的这段时间发生了什么"，需要自己翻消息和面板。

**决定**：离开 ≥6 小时再打开页面时，主对话顶部显示一张只读简报卡：主动消息、今天/已过截止的目标、待查看草稿、失败待重试、可接管线索、新增事实。`GET /api/brief` 由 `lib/brief.mjs` 做纯确定性聚合，不调用模型、不产生状态；可一键关闭，离开不足 6 小时不出现。

**为什么**：产品承诺是"接住思路，继续向前"——接住的前提是回来时能一眼看到进展。简报必须诚实且零成本，所以拒绝让模型来写它：所有条目都来自已有状态，可复核。

**边界**：只在页面打开时出现（不发系统通知）；它是对"回来了"的应答，不属于主动打扰，不受静默时段约束。

## 阶段 19 · 把候选版对齐到真实进度（2026-11-05）

**发现**：外部报告的 issue #1 暴露的不只是一个 bug，而是"一条畸形输入打死整个功能"这一类缺陷；顺着审计还暴露了产品层面的落差——文档写的是"接住思路，继续向前"，真实数据里跟进目标、后台准备与运行记录却是 0，能力都在、入口不在。与此同时 alpha.7 的候选版说明写在上面这些改动之前，已经落后于分支里的真实内容。

**决定**：把健壮性修复与跟进闭环（对话内跟进、一键接管、回来简报）一并收进 alpha.7 的版本说明与变更记录，分支快进合并到 `main` 并重新出本地候选包。创建公开 GitHub Release 仍是需要用户点头的独立步骤，这一轮只要求 `main`、文档与产物三者一致。

**为什么**：`main` 停在 alpha.6 时，从仓库主干拿到这些修复的人一个也没有；而文档与代码分离得越久，"愿景"与"真实进度"的落差越难收敛。合并前先跑完整回归、冻结自测与浏览器验收，是为了让"到达用户"不依赖运气。

**边界**：真实上游模型的工具调用质量仍未评估；后台研究仍需在设置里显式开启；computer use 与邮箱/日历等外部集成仍在路线图。

## 阶段 20 · 从安装到取回草稿（2026-11-23，源码更新）

这次按用户会做的几步验收：从安装路径打开聊天、交代一件有日期的事、关闭主动消息、回来取草稿。公开的 alpha.6 已有面板目标，源码增加了对话入口。原有测试覆盖了多项后台能力，但临时安装路径没有空格，跟进工具的测试还把“网址加日期只盯网址”写成了预期。

| 用户操作 | 查到的落差 | 当前行为与验证 |
|---|---|---|
| 在 Mac 上装好后打开聊天 | 服务健康检查正常，含空格的默认路径却可能找不到页面和凭据。引导接受手写模型或口令后，界面也可能显示成功却没有使用该设置。 | 从临时 `Library/Application Support/Echo` 启动服务，检查页面、模型、口令和存储位置。见 [安装与引导回归](../tests/server-regressions.mjs)。 |
| 在对话中交代一个有截止日期的目标 | 只有日期时保存成手动准备，有日期和网址时只观察来源。临近截止的草稿还可能压掉当天的跟进。 | 日期和网址可以同时观察，每个截止阶段只准备一次。用户改期后，旧日期的依据和时区从当前判断中移除。见 [跟进回归](../tests/commitments-regressions.mjs)。 |
| 回来询问研究进展 | 对话工具只能报告“已有草稿”。仅凭目标描述也可以产出看似有来源的研究成果。 | 可在对话中取回当前草稿及来源。研究结论须引用实际读取的来源，缺证据时保留待澄清问题或显示失败原因。返回简报可直接打开草稿。见 [读回草稿](../tests/follow-up-read-regressions.mjs) 和 [研究回归](../tests/research-regressions.mjs)。 |
| 开启伴随模式 | 原生客户端把查询参数编码进路径，收不到待展示气泡。伴随 OCR 也遗漏了普通看屏流程的屏蔽规则。 | 原生客户端使用带查询参数的请求，伴随与常规采集各自计时。命中排除项时，在模型请求和写盘前返回。见 [原生检查](../tests/companion-ui.swift) 和 [屏蔽规则回归](../tests/companion-regressions.mjs)。 |

Chrome 验收使用临时资料和模拟模型。在主对话交代一个 12 月 1 日截止的设计评审后，后台生成了一份清单；关闭主动消息时，第二条聊天请求仍取回了清单、两条依据和待确认问题。刷新页面后仍能读到这段对话。真实使用中仍待评估的是模型何时会正确调用跟进工具、引用是否支持每个具体结论，以及用户是否愿意采纳这些提醒。

## 阶段 21 · 回答草稿里的问题，核对回复里的记忆（2026-11-23，源码更新）

过去，草稿可以问“这次评审的读者是谁”，用户却只能修改目标或重新对话。现在可以在当前草稿下回答“给第一次接触这个项目的同事看”。回答随原问题保存，下一版草稿会收到这条依据。重复提交同一回答只排队一次，过时的表单会提示用户查看最新草稿。

对话端原本保存了每条回复检索到的事实，现在用户可以在当条回复中查看仍可见的内容。这里说明检索给模型的上下文，无法证明模型实际上采用了哪条事实。这两项改动及另外三个项目的取舍见[开源设计调研](landscape.md)。

## 阶段 22 · 把打扰时机交给可解释的本地规则（2026-11-23，源码更新）

以两位用户在午间收到相同建议为验收场景。一位偏好安静，过去几天常在下午使用 Echo；另一位愿意随时接收建议。两人应当可以得到不同的决定。再把建议换成用户亲自要求的截止日成果，检查触发类型改变时的行为。实现顺序是区分触发来源、计算本地时机、复核实际送达条件，再用真实操作数模型请求。

| 输入 | 决策 |
|---|---|
| 明确交办或采纳的目标，当前有截止节点，或用户要求重新准备、回答了草稿的问题 | 成果优先，可越过根据习惯推测的等待。静默、专注、预算和用户明确给出的时机反馈仍然生效。 |
| 普通建议与伴随气泡 | 可按用户设定的风格和近期聊天时段等待。学习使用最近 14 个本地日期，按每三小时一段记录。至少有 4 个过往活跃日，同一段至少出现在 3 天且占活跃日的 60%，才视为常用时段。 |
| 用户给出「时机不合适」 | 立即安静 30 分钟。同类触发在同一时段有两个不同送达日期收到这种反馈，往后暂缓该类打扰至当前时段结束。按原送达时间归因，晚些时候评价也能记到正确时段。 |
| 相同证据再次触发定时检查 | 若模型上次明确决定保持安静，则在同一本地时段复用判断。证据、相关偏好或时段变化后可重新判断。 |

这些是当前版本的初始规则。统计只说明此人通常何时跟 Echo 聊天。是否真的更受欢迎，需要在真实使用中观察时机反馈；离线测试只能验证分流、送达与模型调用次数。外部参考见[个人助手与主动服务设计](landscape.md)。

## 阶段 23 · 同一预设，选出不同的提醒（2026-11-23，源码更新）

上一版已经能判断何时暂缓，但主动聊天仍然随机抽取建议类型，模型也可以改选话题。两个选择相同风格的人，即使对同一话题给出相反的内容反馈，也没有可靠的选题差异。

现在预设只提供建议间隔、常聊时段等候时长和最低内容分。时机反馈按原送达时间和触发类型归因；近期有规律的聊天日期帮助确定等候窗口。有用性反馈独立影响同类内容和具体事项的排序。计算依据是本人给出的反馈及可观察的使用习惯。

一次定时检查先检查打扰限制，然后在本机选择事项，给入选内容记录来源、排序分和理由。需要组织语言时，模型只收到选定话题、对应证据和允许的措辞偏好。已有成果可以直接呈现。伴随气泡也先从允许的场景中选择可见的具体线索；只有选定的片段进入措辞请求。

验收重放同一组候选项，比较有无话题反馈时谁排在首位，检查实际发出的模型请求，并在所有内容均应暂缓时断言请求数为零。模拟检查验证选择与调用次数，真实用户是否欢迎提醒仍需实际使用评估。

## 阶段 24 · 预览和管理将来的提醒（0.1.0-alpha.8）

「这次内容有用」「这个时间合适」和「以后还想收到这个话题」是三个独立决定。用户可以在主动服务里预览候选事项，直接静音其中一个话题。预览与送达共用排序函数，各自检查对应的打扰限制。静音按个人资料保存。伴随模式在请求措辞前检查已送达的依据，新的线索继续参与选择。

## 阶段 25 · 同一对话里规划、执行和复核（0.1.0-alpha.9）

用户可以先让 Echo 查找相关代码、说明改动，再把这段对话切到执行模式。读取范围、命令批准和文件快照沿用现有权限与运行记录。一次测试先失败、修改后通过时，两次结果都会留下。重复提出相同的失败动作且其间没有成功步骤会结束本轮。个人跟进与工作区执行各自保留原来的授权范围。

## 贯穿始终的十条判断（跨阶段复用的原则）

1. **默认静默**：新能力默认关（屏幕、伴随、后台研究、通知各自独立开关）；要开由用户显式开。
2. **打扰有成本**：任何主动行为都要有预算、间隔、退避和可解释的"为什么"。
3. **遗忘是功能**，不是清理；每次遗忘都要能说出依据。
4. **能解释 > 能自动化**：先让判断可见（意图/缺口/假设/ragione），再谈自动化程度。
5. **尺子冻结**：评估器只增严、隔离沙箱、发布件当被测物；不准为了发版放松判据。
6. **密钥边界**：密钥只在 `data/echo.env`（600）与进程环境，配置里只记"读哪个变量"，永不进 git、不进日志。
7. **可回滚**：改动尽量局部可回退（快照、备份、审批、取消、expired 而非删除）。
8. **不假装**：网关没有的能力不写适配层；模拟结果标成模拟；未验证的事说未验证。
9. **成本转到工程侧**：用户不该为依赖、缓存、权限这些事付代价（DMG 内置依赖、资源版本号、固定安装路径）。
10. **发布流程本身要防呆**：脏树拒绝打包、版本单一来源、包内版本断言、锁文件断言、这份记录必须更新。

## 待决与已知缺口

- **依赖债**：现在是 2 个运行时依赖（MCP SDK、pdfjs-dist）。是否把 MCP 客户端回退为可选（动态 import + 回退实现）以恢复"零 npm 安装即可用"，尚未决定。
- **未验证**：研究质量/漏报率、伴随模式的真实接受度、bandit 的真人数据——都需要真实使用几天后回看 `./bin/echo diag`。
- **未做**：computer use（模型提议、App 执行的 GUI 层）仍在路线图；视频/语音受网关限制。
- **发布与源码**：公开下载为 alpha.6。当前源码和本地安装候选版为 0.1.0-alpha.9，见[候选版说明](release-notes-0.1.0-alpha.9.md)。
- **入口仍少于能力**：跟进的创建现在有对话、一键接管与面板三条路，但文件夹/文档范围的目标、研究开关仍需在本机面板设置。能力与入口的差距是每一轮迭代的主战场。
